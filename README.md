# 城市书房自助借阅与夜间闭馆巡检平台

基于 **Vue 3 + TypeScript + Pinia + Vue Router + Vite** 的单页应用，覆盖读者自助入馆/借阅服务记录、管理员运行总览、**多角色事件协同处置**、**夜间闭馆逐项巡检与人员/图书/设备/公共安全四方交接**、无人值守技防联动、多书房、志愿者巡馆、馆藏调拨、读者信用、亲子阅读活动与突发停电预案。

运行形态：纯前端工程，构建产物由非 root 的 nginx 容器提供服务；业务状态保存在 Pinia 并通过 localStorage 持久化（刷新不丢，便于完整走查业务闭环）。

---

## 原始需求

> 设计城市书房自助借阅与夜间闭馆巡检页面，可使用 Vue 3、TypeScript 和 Pinia。读者刷身份证、借书证或预约码进入城市书房后，页面记录入馆时间、座位、借阅、还书、打印、饮水机和自助设备使用。管理员端展示当前人数、座位占用、未归还图书、设备故障、儿童读者、夜间闭馆倒计时和巡检任务。若读者夜间滞留、图书消磁失败、还书箱满、门禁异常、设备故障、读者遗失物品或闭馆后灯光空调未关闭，页面要让管理员、安保、设备维护和读者服务围绕同一事件处理。闭馆巡检需要逐项确认人员清场、门窗、消防、空调、灯光、自助机和还书箱状态。第二天开馆时，未处理故障、遗失物、投诉和巡检异常会继续提示给管理员。页面还要支持多座城市书房、志愿者巡馆、馆藏调拨、读者信用、亲子阅读活动和突发停电。夜间闭馆不仅是关门，还要确保人员、图书、设备和公共安全都完成交接。对于无人值守时段，页面要把门禁、摄像头、消防、异常声音和读者求助纳入巡检；城市书房作为公共空间，夜间异常需要能快速转给安保和街道值班。

## 一键启动（Docker Compose）

```bash
# 1. 准备环境变量（端口按验证环境，默认 3085）
cp .env.example .env

# 2. 构建并后台启动（多阶段构建，运行镜像为非 root nginx，自带 HEALTHCHECK）
docker compose up -d --build

# 3. 查看健康状态（healthy 即通过）
docker compose ps

# 4. 取实际映射端口并访问
docker compose port app 8080
#   例如输出 0.0.0.0:3085 -> 浏览器访问 http://host.docker.internal:3085

# 验证结束释放资源
docker compose down
```

- 容器内服务端口固定 **8080**，宿主机端口由环境变量 `CC_PUBLISH_PORT` 控制：`"${CC_PUBLISH_PORT}:8080"`，不依赖 3000/8080 等常见端口。
- 健康检查：`GET /healthz`（容器 HEALTHCHECK + compose healthcheck 双重声明）。
- 本应用无数据库/缓存依赖，**不发布任何依赖服务端口**。

> 本地开发（可选）：`npm install && npm run dev`；生产构建（含 vue-tsc 严格类型检查）：`npm run build`。

## 推荐业务流验证（浏览器走查）

1. **读者入馆**：读者服务台 → 选「身份证/借书证/预约码」→ 输入演示号码（身份证 `330106199203152211`、借书证 `LS20210001`、预约码 `YY20260916-08`）→ 分配座位 → 入馆；总览座位图与人数实时变化。
2. **借/还与消磁失败**：服务台选择借书还书、打印、饮水记录；还书时因 1 号自助机故障会**自动生成消磁失败事件**，读者服务（暂扣放行）、设备维护（检修）、安保（核门禁）、管理员（复核归档）在同一事件下按 SOP 接力。
3. **闭馆巡检全流程**：以 admin 登录，总览「🎬 场景演示控制」→「跳到闭馆前 30 分钟」→ 巡检页开始巡检 → 人员清场（可建夜间滞留事件）→ 逐项确认人员清场/门窗/消防/空调/灯光/自助机/还书箱 + 无人值守 5 项（门禁/摄像头/消防/异常声音/求助），勾「异常」会自动建事件 → 四方签字（人员/图书/设备/公共安全）+ 闭馆后灯光空调复核 → 完成交接，**该营业日巡检单立即固化为只读夜间交接档案并自动弹出**；未结事件随档案移交（每件仅挂接一次）。
4. **夜间无人值守**：演示控制「进入夜间无人时段」，在事件详情中对夜间事件「一键转安保调度 / 一键转街道值班」（电话随书房信息展示）。
5. **夜间滞留处置**：闭馆后在巡检页点「📡 闭馆后滞留扫描」，仍在馆读者生成滞留处置单；处置抽屉展示读者身份、所在区域、入闸/无出闸门禁记录与可派安保位置；依次派安保→到场→记录读者解释→管理员**确认劝离 / 特殊延时（看护+截止时间）/ 报警（回执号+自动转街道）**→记录最终离馆时间。**未成年读者（孙小磊）在未联系监护人并记录沟通结果前，决策与离馆按钮均被拦截**，监护人可选择到馆接回。任何滞留未闭环（或未扫描但人还在馆）时，「完成闭馆交接」被阻止，页面列出具体阻塞原因；处置记录随档案固化，第二天管理员可在档案「本夜滞留处置记录」中点开继续查看。
6. **次日开馆验证修复点**：巡检页「🌅 次日开馆」→ 营业日进入次日、生成**全新空白巡检单**（不再是旧单“进行中”）；前夜档案在「夜间交接档案」表与总览中保持已完成、12 项结果、四方签字、完成时间不变；前夜未闭环的还书箱/设备故障/失物仍为遗留待办，事件详情顶部可**回链前夜交接档案**；重复点击开馆幂等（提示已开馆，不重复通知、不改档案）。
7. **突发停电**：总览「模拟突发停电」→ 自动生成紧急停电事件（SOP：应急照明/UPS、清点人数、次生风险、上报街道），相关设备离线；可「恢复供电」。
8. 其余：多书房切换（顶部书房胶囊）、馆藏调拨申请/批准/发运/接收、读者信用加减分、亲子活动报名（+信用）、志愿者巡馆上报。

## 功能与需求对照

| 需求点 | 实现位置 |
| --- | --- |
| 身份证/借书证/预约码入馆，记录时间、座位、借还、打印、饮水、自助设备 | 「读者服务台」、Pinia `branch` store、服务流水 |
| 当前人数、座位占用、未归还图书、设备故障、儿童读者、闭馆倒计时、巡检任务 | 「运行总览」KPI + 座位图 + 夜间技防面板 |
| 七类异常围绕同一事件多角色处理 | 「事件协同中心」+ 事件详情抽屉（SOP、处置留痕、派单/转交/上报/复核/归档） |
| 夜间滞留处置闭环 | 闭馆后滞留扫描（比对门禁出闸）→ 处置单展示**读者身份、所在区域、门禁记录、安保值班位置**；派安保→到场→读者解释→管理员**劝离/特殊延时/报警**三选一→记录**最终离馆时间**；**未成年人强制联系监护人并保留沟通结果（监护人接回）**；未闭环（含在馆未扫描）禁止完成闭馆交接；记录随档案固化、次日管理员可继续查看 |
| 闭馆逐项巡检 | 「夜间闭馆巡检」交接 7 项 + 无人技防 5 项，异常自动生成事件 |
| 次日开馆继续提示 | 未结/遗留事件横幅、事件中心「次日遗留」筛选、`carryOver` 机制 |
| 多书房 | 顶栏书房切换，3 座书房独立数据 |
| 志愿者巡馆 / 馆藏调拨 / 读者信用 / 亲子活动 / 突发停电 | 对应独立页面与 store 动作 |
| 人员/图书/设备/公共安全四方交接 | 巡检页四方签字区，签全且复核后才允许完成交接 |
| **夜间交接档案固化** | 完成交接即固化为只读档案：12 项结果、异常关联事件、四方签字、灯光空调复核、完成时间、闭馆结论、随档案移交的遗留事件清单；任何开馆/重置操作不可改写 |
| **次日开馆（新营业日）** | 「次日开馆」只推进营业日并创建新空白巡检单、恢复可运营设备（故障/离线/满箱保留）；前夜遗留事件继续待办且可从事件详情**回链原交接档案**；重复点击幂等，不重复通知、不改档案 |
| 无人值守门禁、摄像头、消防、异常声音、求助纳入巡检 | 巡检无人技防 5 项 + 「设备与无人技防」页 + 夜间 SOP |
| 夜间快速转安保、街道值班 | 事件详情一键转派，展示调度/街道电话 |

## 目录结构

```
src/
├─ types.ts                 # 全部领域模型
├─ data/
│  ├─ seed.ts               # 3 书房/账号/读者/图书/设备/事件等演示数据
│  ├─ meta.ts               # 类型展示元数据
│  └─ sop.ts                # 15 类事件的多角色 SOP 与权限矩阵
├─ stores/                  # Pinia: auth / system / branch / incident / inspection / stranded / persist
├─ views/                   # 总览/服务台/事件/巡检/设备/馆藏/信用/亲子/志愿者
├─ components/              # AppLayout、IncidentDrawer、HandoverArchiveDrawer、StrandedDrawer、Toast
├─ composables/             # useToast / useIncidentViewer / useArchiveViewer / useStrandedViewer
└─ styles/main.css          # 设计系统样式
Dockerfile                  # 多阶段构建 + 非 root + HEALTHCHECK
docker-compose.yml          # 仅映射应用端口 ${CC_PUBLISH_PORT}:8080
nginx/default.conf          # SPA 兜底 / gzip / 安全头 / healthz
```
