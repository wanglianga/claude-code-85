# 城市书房自助借阅与夜间闭馆巡检平台

基于 **Vue 3 + TypeScript + Pinia + Vue Router + Vite** 的单页应用，覆盖读者自助入馆/借阅服务记录、管理员运行总览、**多角色事件协同处置**、**夜间闭馆逐项巡检与人员/图书/设备/公共安全四方交接**、无人值守技防联动、多书房、志愿者巡馆、馆藏调拨、读者信用、亲子阅读活动，以及本轮新增的 **突发停电与门禁消防应急联动**（停电应急视图、门禁失效机械钥匙/临时开门、读者疏散通告屏、紧急事件升级街道与消防、借还暂存来电补录、空调停运阈值与提前闭馆、夜间六项确认、来电设备自检与跨日交接、街道值班总览、停电复盘）。

运行形态：纯前端工程，构建产物由非 root 的 nginx 容器提供服务；业务状态保存在 Pinia 并通过 localStorage 持久化（刷新不丢，便于完整走查业务闭环）。

## 原始需求（本轮新增：突发停电与门禁消防应急联动）

> 增加突发停电与门禁消防应急联动。城市书房突然停电时，页面切换到应急视图，先展示受影响范围：门禁是否失效、应急照明和疏散指示灯是否点亮、自助借还机和打印机是否离线、消防主机和烟感是否正常、摄像头和异常声音监测是否中断、空调和新风是否停止、当前在馆人数和所在区域。门禁失效时，页面立即通知安保到场，提示是否启用机械钥匙或临时开门，读者端显示疏散路线和集合点，不能只依赖扫码出门。若有人被困、消防通道被占、烟感离线或应急灯不亮，转为紧急事件，同步街道值班和消防联系人，巡检状态不允许完成。停电期间读者的借还请求暂存本地或标记待补录，来电后按操作时间和设备编号补入系统，避免因设备离线把读者算作逾期或借阅失败。空调停运超过阈值时提醒管理员评估是否提前闭馆并通知已预约读者，饮水机和打印设备停止服务要同步到读者端。夜间停电后，管理员和安保逐项确认人员清场、门窗、消防通道、应急照明、门禁恢复和摄像头回传，未恢复前不得标记闭馆完成。来电后设备自检、图书消磁、还书箱和自助机状态重新核验，故障设备进入跨日交接。街道值班人员可看到停电小区、影响书房、在馆人数和处置进展，后续复盘记录停电时间、影响范围、读者求助、处置责任和改进项。

## 原始需求（基础平台）

> 设计城市书房自助借阅与夜间闭馆巡检页面，可使用 Vue 3、TypeScript 和 Pinia。读者刷身份证、借书证或预约码进入城市书房后，页面记录入馆时间、座位、借阅、还书、打印、饮水机和自助设备使用。管理员端展示当前人数、座位占用、未归还图书、设备故障、儿童读者、夜间闭馆倒计时和巡检任务。若读者夜间滞留、图书消磁失败、还书箱满、门禁异常、设备故障、读者遗失物品或闭馆后灯光空调未关闭，页面要让管理员、安保、设备维护和读者服务围绕同一事件处理。闭馆巡检需要逐项确认人员清场、门窗、消防、空调、灯光、自助机和还书箱状态。第二天开馆时，未处理故障、遗失物、投诉和巡检异常会继续提示给管理员。页面还要支持多座城市书房、志愿者巡馆、馆藏调拨、读者信用、亲子阅读活动和突发停电。夜间闭馆不仅是关门，还要确保人员、图书、设备和公共安全都完成交接。对于无人值守时段，页面要把门禁、摄像头、消防、异常声音和读者求助纳入巡检；城市书房作为公共空间，夜间异常需要能快速转给安保和街道值班。

## 一键启动（Docker Compose）

```bash
# 1. 准备环境变量（端口按验证环境，默认 3085）
cp .env.example .env

# 2. 构建并后台启动（多阶段构建，运行镜像为非 root nginx，自带 HEALTHCHECK）
docker compose up -d --build

# 3. 查看健康状态（healthy 即通过）
docker compose ps

# 4. 取实际映射端口并访问
docker compose port app 8080
#   例如输出 0.0.0.0:3085 -> 浏览器访问 http://host.docker.internal:3085

# 验证结束释放资源
docker compose down
```

- 容器内服务端口固定 **8080**，宿主机端口由环境变量 `CC_PUBLISH_PORT` 控制：`"${CC_PUBLISH_PORT}:8080"`，不依赖 3000/8080 等常见端口。
- 健康检查：`GET /healthz`（容器 HEALTHCHECK + compose healthcheck 双重声明）。
- 本应用无数据库/缓存依赖，**不发布任何依赖服务端口**。

> 本地开发（可选）：`npm install && npm run dev`；生产构建（含 vue-tsc 严格类型检查）：`npm run build`。

## 预置演示数据

- **3 座书房**：中山中路（开放，60 座，21:00 闭馆，湖滨街道·中山中路片区）、运河公园（40 座，20:30）、江南里（80 座，已闭馆，含次日遗留事件）；每座书房均配置片区、消防联系人电话、疏散集合点与分路疏散路线。
- 在馆读者 5 人，含 1 名儿童（亲子座，家长陪同信息）；历史夜间滞留记录 1 条。
- 设备在原有门禁/自助机/打印机/饮水机/摄像头/消防主机/空调/照明/还书箱/异常声音/求助/UPS 基础上，为每座书房新增**烟感、新风系统、疏散指示灯**（运河/江南书房补打印机）。
- 未归还/逾期图书、消磁失败图书、在途调拨、失物、投诉、亲子活动、信用流水均有样例。
- 事件中心预置 11 起事件：消磁失败、还书箱满、自助机故障、门磁异常、失物、饮水机故障、夜间摄像头离线+异常声音、江南里夜间滞留/门禁故障/空调未关/座位投诉（**次日遗留**）。

## 推荐业务流验证（浏览器走查）

1. **读者入馆**：读者服务台 → 选「身份证/借书证/预约码」→ 输入演示号码（身份证 `330106199203152211`、借书证 `LS20210001`、预约码 `YY20260916-08`）→ 分配座位 → 入馆；总览座位图与人数实时变化。
2. **借/还与消磁失败**：服务台选择借书还书、打印、饮水记录；还书时因 1 号自助机故障会**自动生成消磁失败事件**，读者服务（暂扣放行）、设备维护（检修）、安保（核门禁）、管理员（复核归档）在同一事件下按 SOP 接力。
3. **闭馆巡检全流程**：以 admin 登录，总览「🎬 场景演示控制」→「跳到闭馆前 30 分钟」→ 巡检页开始巡检 → 人员清场（可建夜间滞留事件）→ 逐项确认人员清场/门窗/消防/空调/灯光/自助机/还书箱 + 无人值守 5 项（门禁/摄像头/消防/异常声音/求助），勾「异常」会自动建事件 → 四方签字（人员/图书/设备/公共安全）+ 闭馆后灯光空调复核 → 完成交接，**该营业日巡检单立即固化为只读夜间交接档案并自动弹出**；未结事件随档案移交（每件仅挂接一次）。
4. **夜间无人值守**：演示控制「进入夜间无人时段」，在事件详情中对夜间事件「一键转安保调度 / 一键转街道值班」（电话随书房信息展示）。
5. **夜间滞留处置**：闭馆后在巡检页点「📡 闭馆后滞留扫描」，仍在馆读者生成滞留处置单；处置抽屉展示读者身份、所在区域、入闸/无出闸门禁记录与可派安保位置；依次派安保→到场→记录读者解释→管理员**确认劝离 / 特殊延时（看护+截止时间）/ 报警（回执号+自动转街道）**→记录最终离馆时间。**未成年读者（孙小磊）在未联系监护人并记录沟通结果前，决策与离馆按钮均被拦截**，监护人可选择到馆接回。任何滞留未闭环（或未扫描但人还在馆）时，「完成闭馆交接」被阻止，页面列出具体阻塞原因；处置记录随档案固化，第二天管理员可在档案「本夜滞留处置记录」中点开继续查看。
6. **次日开馆验证修复点**：巡检页「🌅 次日开馆」→ 营业日进入次日、生成**全新空白巡检单**（不再是旧单“进行中”）；前夜档案在「夜间交接档案」表与总览中保持已完成、12 项结果、四方签字、完成时间不变；前夜未闭环的还书箱/设备故障/失物仍为遗留待办，事件详情顶部可**回链前夜交接档案**；重复点击开馆幂等（提示已开馆，不重复通知、不改档案）。
7. **突发停电与门禁消防应急联动（本轮重点）**，建议用 admin 登录在总览点「⚡ 模拟突发停电」（自动进入全屏应急指挥视图 `/emergency`），按以下顺序走查：
   - **受影响范围**：页面立即切换深色应急视图，逐项展示并可现场核验——门禁是否失效、应急照明/UPS 与**疏散指示灯**是否点亮、**自助借还机/打印机/饮水机**是否离线停止、**消防主机与烟感**是否正常（备用电池）、**摄像头与异常声音监测**是否中断、**空调与新风**是否停止、当前在馆人数与所在区域（按座位自动分区汇总）。
   - **门禁失效**：系统立即通知安保到场，可「安保到场确认」「启用机械钥匙」「临时开门（专人值守、只出不进）」；**读者端通告屏**（`#/reader`）显示分路疏散路线与集合点，明确提示不能只依赖扫码出门、禁乘电梯，并提供分区一键求助。
   - **紧急事件**：点「有人被困 / 消防通道被占 / 烟感离线 / 应急灯不亮」任一，立即升级为**紧急事件**并自动**同步街道值班与消防联系人**，顶部强闪、**巡检状态锁定不允许完成**；险情排除后点「险情排除确认」解锁（受影响设备核验为异常也会自动升级，如现场发现烟感不在线、疏散指示灯不亮）。
   - **借还暂存与补录**：停电中在应急视图登记读者借/还，记录**操作时间 + 设备编号（如人工服务台-T01）+ 经办人 + 条码**；此时读者服务台自助借还被拦截引导暂存。来电并完成设备自检后，可单笔或**一键补录**：按真实操作时间写入流水与馆藏状态（归还按操作时间置回、借阅按操作时间重算到期日），**不会把设备离线期间的读者算作逾期或借阅失败**。
   - **空调阈值 / 提前闭馆**：空调新风停运超过 30 分钟阈值出现提醒，管理员可决定**提前闭馆**，自动统计并通知当日/未来活动已预约读者，读者端同步饮水/打印停止服务与提前闭馆通告。
   - **来电自检与跨日交接**：「确认市电恢复」后对全部设备逐项自检，重点核验**图书消磁、还书箱、自助借还机**；自检失败设备**自动开故障工单进入跨日交接**（沿用既有工单/人工借还/开馆确认链路）。
   - **夜间停电**：可用演示控制「进入夜间无人时段」后再触发停电；来电后必须由管理员/安保**逐项确认六项**（人员清场、门窗、消防通道、应急照明、门禁恢复、摄像头回传），未全部确认前**闭馆巡检无法完成**（完成交接按钮列出具体阻塞原因）。
   - **街道值班总览**：用 `street/street123` 登录进入 `/street`，按**停电小区**聚合查看影响书房、在馆人数、门禁/消防/同步状态与处置进展（核验/清点/自检/夜间确认进度条、暂存补录、求助、提前闭馆通知数），可打开停电/紧急事件与复盘记录。
   - **复盘归档**：设备自检全完成、暂存全补录、夜间六项确认、险情排除后，填写并提交复盘——记录**停电时间（时长）、影响范围、读者求助、处置责任、改进项**，形成只读停电复盘档案，街道端可查。
8. **设备故障跨日交接**：设备页对故障自助借还机/打印机可上传照片、填写影响读者与维修联系人生成工单（同步事件）；完成闭馆并次日开馆后，工单原样保留为「跨日待开馆确认」，页面顶部提示管理员确认 **⛔ 继续停用**（自助机默认启动**人工借还**，服务台顶部出现入口，登记经办人与图书条码，可单笔/一键补入系统）或 **⚠️ 临时恢复**；人工借还结束后系统**自动补生成设备故障说明**（笔数/条码清单/经办人/补录情况，写入工单与事件）。档案中「跨日设备故障工单」可回链查看。
9. 其余：多书房切换（顶部书房胶囊）、馆藏调拨申请/批准/发运/接收、读者信用加减分、亲子活动报名（+信用）、志愿者巡馆上报。

## 功能与需求对照

| 需求点 | 实现位置 |
| --- | --- |
| 身份证/借书证/预约码入馆，记录时间、座位、借还、打印、饮水、自助设备 | 「读者服务台」、Pinia `branch` store、服务流水 |
| 当前人数、座位占用、未归还图书、设备故障、儿童读者、闭馆倒计时、巡检任务 | 「运行总览」KPI + 座位图 + 夜间技防面板 |
| 七类异常围绕同一事件多角色处理 | 「事件协同中心」+ 事件详情抽屉（SOP、处置留痕、派单/转交/上报/复核/归档） |
| 夜间滞留处置闭环 | 闭馆后滞留扫描（比对门禁出闸）→ 处置单展示**读者身份、所在区域、门禁记录、安保值班位置**；派安保→到场→读者解释→管理员**劝离/特殊延时/报警**三选一→记录**最终离馆时间**；**未成年人强制联系监护人并保留沟通结果（监护人接回）**；未闭环（含在馆未扫描）禁止完成闭馆交接；记录随档案固化、次日管理员可继续查看 |
| **设备故障跨日交接** | 故障工单保留**照片、报修时间、影响读者、维修联系人**到次日；开馆前管理员确认**继续停用（可启用人工借还兜底）/临时恢复**；**临时人工借还登记经办人与图书条码、单笔/一键补入系统，结束后自动补生成设备故障说明**；工单写入交接档案可回链 |
| 闭馆逐项巡检 | 「夜间闭馆巡检」交接 7 项 + 无人技防 5 项，异常自动生成事件 |
| 次日开馆继续提示 | 未结/遗留事件横幅、事件中心「次日遗留」筛选、`carryOver` 机制 |
| 多书房 | 顶栏书房切换，3 座书房独立数据 |
| 志愿者巡馆 / 馆藏调拨 / 读者信用 / 亲子活动 / 突发停电 | 对应独立页面与 store 动作 |
| 人员/图书/设备/公共安全四方交接 | 巡检页四方签字区，签全且复核后才允许完成交接 |
| **夜间交接档案固化** | 完成交接即固化为只读档案：12 项结果、异常关联事件、四方签字、灯光空调复核、完成时间、闭馆结论、随档案移交的遗留事件清单；任何开馆/重置操作不可改写 |
| **次日开馆（新营业日）** | 「次日开馆」只推进营业日并创建新空白巡检单、恢复可运营设备（故障/离线/满箱保留）；前夜遗留事件继续待办且可从事件详情**回链原交接档案**；重复点击幂等，不重复通知、不改档案 |

| **门禁失效应急** | 停电即自动通知安保到场；安保到场确认、**机械钥匙**、**临时开门（只出不进专人值守）**；读者端通告屏展示分路疏散路线/集合点/禁乘电梯/一键求助，明确不能只靠扫码出门 |
| **紧急事件升级（被困/通道被占/烟感离线/应急灯不亮）** | 一键升级紧急事件并**自动同步街道值班与消防联系人**；现场核验烟感/疏散指示灯异常同样自动升级；**巡检状态锁定不允许完成**，险情排除确认后解锁 |
| **借还暂存 + 来电补录** | 停电期借还记录真实操作时间/设备编号/经办人/条码；来电自检后单笔或一键按**操作时间+设备编号**补入流水与馆藏状态，归还按操作时间置回、借阅重算到期日，**避免误算逾期/借阅失败** |

| **夜间停电六项确认** | 来电后管理员/安保逐项确认人员清场、门窗、消防通道、应急照明、门禁恢复、摄像头回传；未全部确认不得标记闭馆完成 |
| **来电自检/消磁/还书箱核验 + 跨日交接** | 全设备逐项自检，重点自助机消磁通道、还书箱、门禁；自检失败自动开故障工单进入跨日交接（复用既有工单/人工借还链路） |
| **街道值班总览** | `street/street123` → `/street`：按停电小区聚合影响书房、在馆人数、门禁/消防/同步状态与处置进展进度、紧急事件、暂存补录、求助、提前闭馆通知数 |
| **停电复盘** | 复盘记录停电时间（时长）、影响范围、读者求助、处置责任、改进项，归档为只读档案供街道追溯 |
